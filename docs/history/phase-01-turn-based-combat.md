# Phase 01: turn-based-combat-foundation 実施記録

## フェーズの目的

固定マップ上で、ジャンゴと敵1体によるターン制グリッド移動と素手戦闘が成立する
最小プレイアブル版を実装する。

完成条件：歩く・待機する・敵が追跡する・隣接した敵を殴る・敵から攻撃を受ける・
どちらかが倒れる・再開できる。

## 実装した内容

- Vite + TypeScript + Phaser 3 + Vitest の最小構成を新規作成（リポジトリが実質空のため）
- ゲームロジックを `src/game/` 配下に描画非依存で実装し、Phaser シーン
  （`src/main.ts`）から呼び出す構成にした
  - `types.ts`：座標・方向・マップ・アクター・ゲーム状態の型定義
  - `map.ts`：固定マップ生成、境界/壁判定、斜め移動の角抜け禁止判定
  - `direction.ts`：隣接方向の算出、8方向→4方向変換（描画用）
  - `turn.ts`：1入力=1ターンの処理（移動/攻撃解決→敵行動→死亡判定→ターン加算）
  - `state.ts`：初期状態生成（再スタート時にも同じ関数を使用）
  - `input.ts`：キー入力→アクションへのマッピング
- 固定マップ（10x8、外周壁＋中央に独立した壁ブロック）を1つ用意
- プレイヤー：WASD移動、QEZC斜め移動、Space待機、HP3、攻撃力1
- 戦闘：隣接8方向への移動入力で素手攻撃（移動はしない）、敵HP2、撃破で盤面除去、
  撃破した敵はその後行動しない
- 敵：プレイヤーに隣接していれば攻撃、そうでなければ単純追跡（進めない場合は待機）
- ゲーム状態：HPとターン数を画面上部に表示、ゲームオーバー/勝利をテキストで表示、
  Enterキーで初期状態へ再スタート
- 素材：提供されたプレイヤー(`player.png`)と敵(`bok_lv1.png`)のスプライトシートを
  `public/assets/sprites/` に配置し、Phaserのスプライトとして使用した。
  各シートは3列(フレーム)×4行(方向: 上/右/下/左)、1セル24x32pxで、
  各方向の中央フレーム(2枚目)を静止姿勢として表示している。表示のみ1.5倍拡大
- 背景色(0x00ff00)は完全一致ピクセルを透過化して除去済み（画像を直接上書きせず、
  透過済みのコピーとして配置）
- 待機中（移動していない間）も、現在の向きの歩行アニメーション（1→2→3→2）を
  その場でループ再生し続ける（足踏み）。移動時は同じループを継続させたまま
  トゥイーンで座標のみを動かし、方向が変わった場合のみアニメーションを切り替える
- 歩行アニメーションの再生速度を落とし（frameRate 10→4）、足踏みらしいテンポにした
- 移動トゥイーン実行中は新たな入力（キー長押しによるOSのオートリピートを含む）を
  無視するガードを追加。以前は長押し時に複数ターンが重なって処理され、
  敵や自キャラのスプライトが壁をすり抜けたように見える表示崩れが発生していたため
- 左向きフレームの縁にドットが見えていた件は、Phaserのデフォルト（線形補間）で
  拡大表示した際に隣接フレームのピクセルが滲んだことが原因と判明。
  `pixelArt: true` を指定して最近傍（ニアレスト）フィルタリングに切り替えて解消した
  （幅24px自体の切り出し位置は実測どおり正しく、フレーム境界に問題はなかった）

## 主要な仕様判断

- 壁やマップ外への移動入力はターンを消費しない（仕様書のblocked_movement_policyに従う）
- 攻撃判定は「移動先が敵の現在座標と一致するか」で行い、一致すれば移動ではなく攻撃として解決する
- 敵の追跡は「プレイヤーへの相対方向（斜めを含む）を優先し、進めなければ水平/垂直成分を試す」
  単純なグリーディ法とし、経路探索は実装していない
- 4方向素材変換用の関数 (`toDirection4`) は用意したが、実際の素材が無いため
  現在は向き表示（三角形の角度）にのみ使用している

## 自動テスト結果

Vitest: 4ファイル / 20テスト、すべて成功。

対応範囲：8方向移動量、壁/マップ外移動の禁止、斜め角抜け禁止、隣接方向への移動が
攻撃になること、攻撃時に敵マスへ移動しないこと、攻撃/待機でターンが進むこと、
通常移動後に敵が行動すること、敵HP0での除去、撃破された敵が反撃しないこと、
プレイヤーHP0でのゲームオーバー、無関係なキーでターンが進まないこと、
再スタートで初期状態に戻ること。

## 判明した問題・制約

- 移動アニメーションはトゥイーン(220ms)に同期させたが、厳密なフレーム単位の
  歩数同期ではなく、ループ再生してトゥイーン完了時に停止する簡易実装とした
- サンドボックス環境にブラウザがなく、目視での手動確認ができていない
- production buildでPhaser同梱により1ファイルが500KB超という警告が出るが、
  ビルド自体は成功しており、フェーズ1の要件外のため対応していない
