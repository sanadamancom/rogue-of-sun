# Phase: phase-06-kraken-telegraphed-tentacle-strike

## 目的と対象範囲

クラーケン（kraken）を「移動しない地点指定型の範囲攻撃役」として実装し
た。プレイヤーの現在位置を予告地点として保存し、次回行動でその地点を中
心とする十字5マス（中心＋上下左右）を攻撃する。壁越しでも予告でき（コ
カトリスの直線射撃とは異なり視線を要求しない）、命中時はダメージに加え
てクラーケン方向へ1マス引き寄せる。触手の演出・アニメーション・攻撃範
囲の視覚的マーカー・水タイル・継続ダメージ・状態異常・クラーケンの召喚
能力など、今回の仕様に含まれない要素は追加していない。commit・push・PR
作成は行っていない。

## 採用したクラーケンの状態管理

クラーケン個体ごとに`EnemyActor.tentacleTarget?: Vec2`を追加した。8方向
やbooleanではなく座標そのもの（`optional_position`）を保持する。他種の
個体状態（コウモリの`retreating`、アックスの`recovering`、マミーの
`restingAfterMove`、コカトリスの`gazeDirection`）とは完全に独立したフィ
ールドで、共有・グローバルな予告座標は使用していない。プレイヤー側には
クラーケン専用の状態を追加していない（`Actor`型は変更なし）。

フロア生成時は`createInitialEnemy`で毎回新しい`EnemyActor`が作られるた
め、フロア移行・Enter再開・N新規seed・クラーケン撃破のいずれでも
`tentacleTarget`は自動的に未設定（undefined）から始まり、追加のリセット
処理は不要だった（既存の他種実装と同じ構造）。

## 射程と予告条件

- 距離指標はChebyshev距離（`chebyshevDistance`、コウモリの離脱実装です
  でに導入済みの関数をそのまま再利用）。
- 予告条件：クラーケンが未予告状態（`tentacleTarget`未設定）／プレイヤ
  ーが生存している／プレイヤーがChebyshev距離1〜5にいる／プレイヤーの
  現在マスが床である（`isWalkable`で確認。実際には常に真だが仕様どおり
  明示的にチェックした）。
- 視線判定は行わない（`line_of_sight.required: false`）。触手は地面から
  出現するという設定であり、コカトリスの壁で遮断される直線射撃とは明確
  に差別化した。壁越しでも予告できることを新規テストで確認済み。
- 予告時にプレイヤーの「現在座標」をそのまま`tentacleTarget`へ保存す
  る。乱数は一切使用していない。

## 十字5マスの攻撃範囲

`tentacleCrossCells(map, center)`が、保存済み中心座標と、その上下左右の
計5マス（`{center}`, `{x, y-1}`, `{x, y+1}`, `{x-1, y}`, `{x+1, y}`）を
返す。マップ外の座標は`isInBounds`で除外する。壁マスは範囲の座標として
は除外しない（表示上の範囲に含めてよいという仕様どおり、壁自体への特別
処理は行っていない。プレイヤーは壁マスに存在し得ないため、命中判定の結
果には影響しない）。命中判定はこの5マスのいずれかにプレイヤーが現在い
るかどうかだけで行い、他の敵の有無は一切見ない（遮断もしない）。

## 予告から攻撃までの実測周期

新規テストおよび手動シミュレーションで以下を確認した。

1. 非予告・距離1〜5：その場から動かず、攻撃もせず、`tentacleTarget`に
   プレイヤーの現在座標を保存して`kraken_tentacle_aim`を1件だけ出す
   （同じ行動では攻撃しない）
2. 次のそのクラーケンの行動順：保存済み中心へ十字攻撃を発動する。プレ
   イヤーが範囲外に逃げていても、隣接していても、必ず保存地点に対して
   判定する。攻撃後は`tentacleTarget`を解除し、攻撃は連続しない（次の
   ターンは条件を満たせば再予告、満たさなければ待機）
3. クラーケンはいかなる行動でも移動せず、非予告・隣接時であっても通常
   近接攻撃を一切行わない（`tryMeleeAttack`を呼び出さない専用の解決関
   数として実装）

## ダメージと引き寄せの処理

- ダメージはクラーケンの既存`attack`値（変更していない、`hp:6`/
  `attack:2`のまま）をそのままプレイヤーHPへ適用し、`player.hp === 0`
  で`player.alive = false`にする、既存の近接攻撃と同じダメージ・敗北判
  定パターンを再利用した。新しい固定ダメージ値をハードコードしていな
  い。
- 引き寄せはダメージ適用後、プレイヤーが生存している場合だけ試行する。
- 引き寄せ方向の決定規則（`pull_direction.algorithm`どおり）：
  `dx = enemy.pos.x - player.pos.x`、`dy = enemy.pos.y - player.pos.y`
  （プレイヤーからクラーケンへの向き）を求め、`abs(dx) >= abs(dy)`なら
  x方向（同値時はx優先、仕様どおり）、そうでなければy方向へ1マス移動さ
  せる。判定は乱数を使用せず常に決定的。
- 引き寄せ先の妥当性：マップ内かつ床（`isWalkable`を再利用）、クラーケ
  ン自身のマスでない、他の生存中の敵がいない、の3条件をすべて満たす場
  合だけ実際に移動させる。いずれかを満たさない場合は「ダメージだけを適
  用し、引き寄せは行わない」（攻撃自体は成功のまま、引き寄せ失敗によっ
  て命中判定を巻き戻さない）。
- 引き寄せ先が出口タイルであっても、この処理内でフロア移行を発生させ
  ない（フロア移行判定は`processTurn`側の既存ロジックにすでに委譲され
  ており、クラーケンの解決関数はプレイヤー座標を更新するだけで、フロア
  移行や敵撃破判定などの以降の既存ステップに一切介入していない。新規テ
  ストで、引き寄せ先を出口座標に一致させても`phase`が`'playing'`のまま
  で`floor_advanced`イベントが出ないことを確認した）。
- 引き寄せはプレイヤーの追加行動・追加の敵ターンを消費しない（同一
  `processTurn`呼び出し内で完結し、`state.turn`は通常どおり1回だけ増加
  することを確認済み）。

## 追加したイベントと表示文章

| イベント | データ | 表示文章 |
|---|---|---|
| `kraken_tentacle_aim` | `enemyId`, `target` | 「クラーケンが足元を狙っている！」 |
| `kraken_tentacle_strike`（hit） | `enemyId`, `target`, `hit`, `damage` | 「クラーケンの触手が襲いかかり、{damage}ダメージ！」 |
| `kraken_tentacle_strike`（miss） | 同上 | 「クラーケンの触手が空を切った。」 |
| `player_pulled` | `sourceEnemyId`, `from`, `to` | 「触手に引き寄せられた！」 |

表示名は`ENEMY_DEFINITIONS`の一元化された`displayName`から取得してお
り、`turn.ts`側に完成文章を直接書いていない。命中時のイベント順は
`kraken_tentacle_strike`→（引き寄せ成功時のみ）`player_pulled`の順で
`resolveKrakenEnemy`内でこの順に`events.push`しており、実際の処理順と
一致している。`player_defeated`は既存の`processTurn`側の仕組みにより、
全敵の行動解決が終わったあとに中央で1回だけ追加される（下記「既存の敗
北イベント仕様」の節を参照）。通常攻撃（`enemy_attack`）は使用していな
いため、命中時に通常攻撃メッセージと二重表示される心配はない。既存の直
近3件保持規則（`MessageLog`）は変更していない。

**仕様のデータ定義に対する軽微な拡張**：yaml内`events.add.*.data`には
`enemyType`が明記されていないが、命中・失敗表示の区別や正式な敵表示名
の取得（`formatting: 正式な敵表示名を使用する`という要件）のため、既存
のコウモリ／マミー／コカトリスの各イベントと同じ設計方針に合わせて
`enemyType`フィールドも各イベントに含めた。矛盾ではなく最小限の一貫性
のための拡張と判断し、実装を停止せずそのまま進めた。

## 既存の敗北イベント仕様への対応

`event_order_on_hit`は
`kraken_tentacle_strike → player_pulled_if_successful → player_defeated_if_applicable`
の順を求めている。既存の`processTurn`は`player_defeated`イベントを個々
の敵の行動内では発行せず、`resolveEnemiesAction`が全敵の行動を（プレイ
ヤー死亡時は早期停止しつつ）解決し終えたあとに、中央で1回だけ
`!state.player.alive`を見て追加する設計になっている。クラーケンの解決
関数はこの既存の仕組みに一切手を加えず、`kraken_tentacle_strike`→（成
功時）`player_pulled`の順にイベントを積むだけで、`player_defeated`は既
存のとおり最後に中央で追加される。結果として要求された順序は自然に成立
しており、敗北イベント仕様を変更する必要も、敗北処理を複製する必要もな
かった。新規テストで、HPが0になった場合に`player_defeated`が1回だけ生
成されることを確認している。

り、複数敵の非干渉テストのうち2件は、相手役に選んだ敵（近接攻撃可能な
bokや、あらかじめ予告済みにした別のクラーケン）が同じターン内で独立に
行動してしまうテスト設計上の見落としがあり、いずれもテスト側（相手役を
「射程外で行動しない別のクラーケン」に変更）を修正して解消した。実装コ
ード自体の修正は行っていない。

## commit可能かどうか

自動テスト・型チェック・ビルドはすべて成功しており、コード変更として
はcommit可能な状態にある。ただし本タスクの指示（`repository_rules`：
commit・push・PR作成を行わない）に従い、commitは行っていない。実画面
での`manual_validation`項目（回避操作の手触り、メッセージ表示、引き寄
せの見た目など）を確認したうえでのcommitを推奨する。これにより通常敵で
固有挙動が未実装の種族はいなくなる。
