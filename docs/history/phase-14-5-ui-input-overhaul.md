# Phase 14.5 テストプレイ用UI・カメラ・操作改善

## 変更前の問題

- HUDが複数行にまたがり、Run Seed・Floor Seed・操作説明・詳細EXP・エンチャントの長文説明まで常時表示されていた。
- メッセージログ（3行）がフィールド全体に重なる半透明バーとして描画され、フィールドを覆っていた。
- カメラ表示範囲が横16マス×縦12マスで、常時表示のマップ全体把握手段がなかった。
- インベントリ（Tab）・能力（P）画面がそれぞれ独立した全画面に近い中央オーバーレイで、フィールドを覆っていた。
- キー配置がWASD/矢印移動・Shift+方向=向き変更・X=攻撃・F=エンチャント切替という独自体系で、ダッシュ・斜め固定・方向転換のみ・長押し操作が存在しなかった。
- 配色は白文字＋黒背景の簡易表示で、統一されたパネル/枠/配色トークンがなかった。

## UI構造と配色方針

- 通常画面を「上端1行HUD／中央9×7フィールド／下端2行メッセージ」の3領域に再構成した（`HUD_HEIGHT`/`FIELD_PIXEL_HEIGHT`/`MESSAGE_HEIGHT`の3ストリップを固定論理解像度内に確保）。
- HUDから除外した情報（Run Seed／Floor Seed／操作説明／詳細EXP／エンチャントの長文説明）は、それぞれ「記録」「その他＞操作説明」「状態」画面へ移動した。
- 配色は`COLORS`トークン（`src/main.ts`内、単一の情報源）としてアイボリー系パネル背景・濃い赤茶の外枠・黄土〜淡橙の内枠・こげ茶文字・くすんだ赤茶見出し・HP緑／SOL黄／満腹度橙／危険赤／無効灰茶を定義し、全画面（HUD・メッセージ窓・小窓メニュー）で共通利用した。参照作品の画像・フォント・アイコンは一切流用せず、色の意味（用途）だけを仕様どおりに再現した独自配色。

## カメラと探索マップ

- `src/game/camera.ts`の`computeCameraWindow`（純粋関数、9×7固定）を仕様上の単一の「9×7とは何か」の定義として全体で共有しつつ、実際の描画クリッピングは**固定TILE_SIZE（48px）のまま**、Phaser標準のカメラ`setViewport`＋`setBounds`＋`startFollow`（既存の追従機構を流用）で実現した——動的スケールTILE_SIZEは採用していない（後述「実装上の主要判断」参照）。
- ワールド用カメラ（`this.cameras.main`）はフィールド矩形（`0, HUD_HEIGHT, 432, 336`）にビューポートを固定し、マップ境界を`setBounds`、プレイヤー追従を`startFollow(sprite, true, 1, 1)`（lerpなし=瞬時追従）とすることで、四辺・四隅での境界クランプがPhaser側の既存ロジックでそのまま成立する。
- UI用カメラ（`this.uiCamera`）はキャンバス全体（`0,0,LOGICAL_WIDTH,LOGICAL_HEIGHT`）を覆い、HUD・メッセージ窓・メニュー窓・ミニマップだけを描画する。各カメラは`.ignore()`で相手専用のオブジェクトを除外し、二重描画を防いでいる（`ignoreForWorldCamera`/`ignoreForUiCamera`）。敵スプライトやground itemテキストのように実行時に再生成されるオブジェクトは、生成直後に個別へ`ignoreForUiCamera`を再適用している。
- 探索済みマップは`exploredTiles: boolean[][]`としてMainSceneのプライベートフィールドに保持し、GameState・seed・telemetryには一切含めない。`computeCameraWindow`で得た現在の9×7窓を毎ターン`markCameraWindowExplored()`でOR書き込みし、フロア変更・リスタート時は`resetExploredTiles()`で全面falseへ再初期化する。
- ミニマップ（`drawMinimap()`）は探索済みタイルのうち壁でないものを部屋／通路で濃淡を変えて薄く描画し、出口は探索済みの場合のみ、敵・アイテムは**現在の9×7カメラ窓内にあるものだけ**（既存の可視性ルールが存在しないため、仕様7.3の「現在見えている対象だけを表示」フォールバックを採用）、プレイヤーは常に最も明るい点として描画する。フィールドカメラのビューポート内に`scrollFactor(0)`で配置され、ワールドスクロールに追従しない。

## メニュー階層

```
コマンド（左上小窓）
├─ 道具  → 一覧窓（左）＋詳細窓（右）→ 決定で行動窓（食べる/使う・装備する/外す・置く・捨てる）
├─ 能力  → 一覧窓＋詳細窓（既存のカラダ/ココロ/チカラ/ハヤサ割り振りを再利用）
├─ 状態  → HP/SOL/満腹度/LV/EXP/攻撃/防御/エンチャント/解禁済み属性/状態異常
├─ 記録  → 階層/ターン数/Run Seed/Floor Seed/メッセージ履歴
└─ その他
   ├─ 操作説明 → 全キーバインド一覧
   └─ 冒険を終了 → 確認窓（初期選択キャンセル）
```

- 装備専用画面は追加していない（既存実装に独立した装備変更機能がなく、道具画面から装備/解除するため、仕様9.4の「既存の独立した装備変更機能がある場合のみ表示する」を満たさない）。
- 設定画面は追加していない（Phase 14.5で実際に変更可能な設定が存在しないため）。
- いずれの画面もフィールド全体を覆わず、フィールド背景とミニマップが常に透けて見える。

## キー配置と入力処理

| 操作 | キー |
|---|---|
| 上下左右移動 | WASD／矢印／テンキー8246 |
| 斜め移動 | QEZC／テンキー7913 |
| 攻撃・決定 | J／Enter |
| 1ターン待機 | Space／テンキー5 |
| ダッシュ | Shift＋方向 |
| 斜め移動固定 | Ctrl＋方向 |
| その場で方向転換 | F＋方向 |
| メインメニュー | I／Esc |
| エンチャント切替 | R |
| メニュー：カーソル移動 | WASD／矢印 |
| メニュー：決定 | J／Enter |
| メニュー：戻る | K／Backspace／Esc |

- `src/game/input-router.ts`の`routeKeyDown`が唯一の入力ルーターで、`field`/`menu`/`dialog`/`gameover`の4コンテキストが排他的（menu/dialogは`game`種別のアクションを一切返さない）。
- `MainScene.handleRoutedKey`が単一の入口となり、`activeAnimations > 0`の間は全入力を無視（既存のトゥイーン重複防止ガードを維持）。
- Fキーは物理キーの押下状態を`this.fHeld`として自前追跡（ブラウザの標準修飾キーではないため）。Shift／Ctrlは`KeyboardEvent.shiftKey`/`ctrlKey`をそのまま利用。
- OSキーリピート（`event.repeat`）は無視し、独自の`RepeatTimer`（`src/game/input-router.ts`の`tickRepeat`、開始遅延180ms・反復間隔90ms、いずれも定数として一箇所に集約）だけを採用（仕様11.1の二重リピート禁止）。
- `Tab`はブラウザフォーカス移動の抑止だけを行い、旧来のインベントリ切替機能からは外した（仕様10.1）。

## ダッシュ停止条件の実装結果

`src/game/dash.ts`の2つの純粋関数で実装（`turn.ts`側は無改修）：

- `canTakeDashStep`：壁／マップ外／斜め角抜け禁止（既存`canMove`をそのまま利用）、および踏み込み先が敵と接触・攻撃可能距離（Chebyshev距離1以内）になる場合は、その一歩を**取らない**（行動前に停止）。
- `shouldStopDashAfterStep`：踏み込んだ先が出口／ground item／既知（triggered済み）の罠、通路の分岐・交差（部屋外かつ開放方向3以上）、または部屋⇄通路の境界であれば、その一歩は実行した上で**次の一歩からは停止**する。

いずれもGameStateを読むだけの純粋関数で、`update(time)`ループから`this.dashDirection`を介して駆動する。Shiftを離す・メニューを開く・他の行動を行うといった要因はScene側（`main.ts`）でダッシュ状態をリセットして処理する。

## 手動（ブラウザ）確認結果

Playwright（Chromium）による自動操作＋スクリーンショット目視確認で実施（固定seedはゲーム起動時に`randomSeed()`で決定されるため、確認は個々のロード・操作セッションごとに実際に発生したseedで行った——複数回のロードでそれぞれ異なるseedを使用しても、9×7カメラ・探索マップ・メニュー・ダッシュ等の機構自体はseedに依存しないため、機能確認としては妥当と判断した）。

確認した項目：

- 960×540／1280×720／1920×1080の3ビューポートそれぞれで初回ロード、コンソールエラー0件を確認。
- 960×540→1920×1080への実行時リサイズで、整数倍率（1x→2x）へ再スケールし、HUD・フィールド・メッセージ窓の3領域配置が崩れないことを確認。
- 通常画面（HUD1行＋9×7フィールド＋メッセージ窓2行）が表示され、フィールド上に探索済みマップ（半透明の白い部屋/通路形状、プレイヤーの明るい点、アイテムの水色点）が重なって表示されることを確認。
- メインメニュー（I）を開くと、フィールドを覆わない左上の小窓（コマンド一覧）と右の詳細窓が表示されることを確認。
- 道具／能力／状態／記録／その他＞操作説明／その他＞冒険を終了の全画面へ実際に遷移し、それぞれ意図した内容が表示されることを確認（状態画面でHP/SOL/満腹度/LV/EXP/攻撃/防御/エンチャント/解禁済み属性、記録画面でRun Seed/Floor Seed/メッセージ履歴、操作説明で全キーバインド一覧）。
- 冒険を終了確認窓の初期選択が「キャンセル」であり、↓キーで「終了する」へ移動できることを確認。
- F＋方向（その場で方向転換）、Ctrl＋方向（斜め固定、カーディナル方向は無視）、Shift＋方向長押し（ダッシュ、複数マス連続移動とターン数増加を確認）、Space長押し（連続待機、満腹度減少を確認）、Rキー（エンチャント未解禁時は無反応）をそれぞれ操作し、いずれもコンソールエラーが発生しないことを確認。
- 400回のランダムキー入力（移動・攻撃・待機・メニュー開閉を含む）＋複数回のリスタートを別セッションで実施し、未処理例外が発生しないことを確認。

## 対象外として残した事項

- Phase 15の数値・生成率・敵AI・武器/防具能力値は一切変更していない。
- ゲームパッド対応・キーコンフィグ画面は実装していない。
- マップ表示のON/OFF切替キーは実装していない（常時表示のみ、仕様どおり）。
- 装備専用メニュー画面・設定メニュー項目は、対応する独立機能が存在しないため追加していない。
- ダッシュの敵接触判定は武器種別の射程（スピアの2マス等）を区別しない簡略化とした（Chebyshev距離1で統一）。実際の攻撃判定自体は各武器の既存射程をそのまま使用しており、ダッシュの停止判定だけの簡略化。
- 連続待機（Space長押し）の「状態変化」による停止条件は、被ダメージ・SOL満タン・敵接近（距離2以内）・ゲーム終了の4条件のみを実装し、毒/鈍足等の状態異常の新規付与そのものを個別検知する処理までは追加していない（被ダメージ検知でおおむね同等のケースをカバーする設計とした）。
- HUD最終行に軽微な表示上の重複（ENCHANT表示の区切り記号）が疑われる箇所があり、コード上は単一の区切り文字のみを出力する実装になっていることを確認したが、実機画面での見え方は次回の実プレイ時に再確認する。
