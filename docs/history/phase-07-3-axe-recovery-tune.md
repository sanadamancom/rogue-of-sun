# Phase 07.3 アックス攻撃後硬直の成立化

## 確認された問題（Phase 07.2訂正監査より）

- プレイヤー初期HPは3、アックスの攻撃力は3だった。
- この組み合わせでは、アックスの攻撃が1回命中した時点でプレイヤーが死亡していた。
- そのため、アックスの「攻撃成功後1ターン強制休止」という既存挙動（`recovering`フラグ、`enemy_recovering`イベント）は、発動する頃には既にプレイヤーが死亡しており、反撃・離脱・位置調整の機会として機能していなかった。

## 分類の確定

- 対象：アックス
- 分類：**TUNE**（REDESIGNではない）
- 理由：攻撃後硬直という独立した挙動自体は既存構造としてすでに実装されている。問題は攻撃力の数値だけがその挙動を利用不能にしていたことであり、AIや状態遷移の再設計は不要。攻撃力を下げるだけで既存構造のまま役割が成立する。

## 変更内容

- `src/game/enemy-def.ts`：`axe.attack` を `3` から `2` へ変更。
- 攻撃力の定義箇所はこの1か所のみであり、戦闘・表示ともに同じ`ENEMY_DEFINITIONS`を参照するため、他に数値を反映させる箇所の変更は不要だった。

## 維持した仕様

- アックスHP：6（変更なし）
- `behaviorType: 'recovery_melee'`（変更なし）
- 通常の8方向chase移動（変更なし）
- 攻撃成功後に`recovering=true`となる処理（変更なし）
- 次の敵行動機会で強制休止する処理（変更なし）
- `enemy_recovering`イベントおよびメッセージログ表示（変更なし）
- 出現対象・出現確率・重複出現（変更なし）
- 他の敵（ゴーレム・スパイダー等）の数値・挙動（変更なし）
- プレイヤーのHP・攻撃力（変更なし）

## 追加・更新したテスト

`src/game/__tests__/enemy-behavior-melee-variants.test.ts` に新規describeブロック
`'axe recovery exploitability at real definition values (phase-07-3-axe-recovery-tune)'`を追加し、以下を実測で確認した。

- `ENEMY_DEFINITIONS.axe.attack`が実装値として`2`であること
- 満タンHP3のプレイヤーがアックスの1撃を受けてHP1で生存すること（`state.player.alive`が`true`のまま）
- 攻撃直後、アックスが次の行動機会で隣接中でも攻撃も移動もしないこと（`enemy_recovering`挙動）
- HP2のプレイヤーはアックスの1撃で死亡すること（HP0、`alive`が`false`）

既存の`axe (recovery_melee) behavior`ブロックのテスト（`attack: 3`を明示的に渡す形式）は、recovery_meleeという挙動メカニズム自体を汎用的な攻撃力で検証するテストであり、実際のゲームバランス値とは独立しているため変更していない。
