# Phase 07.5 ゴーレムHP調整

## Phase 07.4の確定分類とその内容

Phase 07.4（限定プレイテスト、通常画面相当の情報だけを使うprocessTurn駆動シミュレーション）の確定分類は**TUNE**でした。問題はゴーレムの攻撃力ではなく、HP8による攻防の反復回数と、長期戦にともなう退路依存にあると判断されました。

確認された事実（Phase 07.4より）：
- 十分な退路がある場合、隔ターン停止を利用して被弾なしで撃破できた。
- 狭い場所では、周期を正しく予測できていても、HP8を削り切る前に退路が尽きる事例があった。
- HP8では安全な攻撃機会（2ターンに1回）を8回繰り返す必要があり、約16ターンを要した。
- HP8は周期の理解を深める方向ではなく、同じ攻防の反復回数を増やす方向に寄与していた。

**注記**：Phase 07.4は実際のキャンバス画面を人間が操作したプレイテストではなく、通常操作と同等の情報だけを使うヘッドレスシミュレーションです。今回のHP変更はこのシミュレーション結果を数値調整の根拠として使用していますが、人間による実画面での視認性・体感確認が完了したものとしては扱っていません。

## 変更内容

- `src/game/enemy-def.ts`：`golem.hp` を `8` から `4` へ変更。
- ゴーレムのHP定義箇所はこの1か所のみで、他に数値を反映させる箇所はありません。

- `enemy_recovering`イベントおよび停止メッセージ
- 同一フロアのゴーレムの同期位相
- 出現可能フロア・出現数・重複出現可否・配置規則
- 名前、sprite、移動能力
- プレイヤーHP・攻撃力・操作、ターン処理、ダメージ計算
- 他の敵（アックス等）の数値・挙動・出現方式
- フロア生成、UI・メッセージ文言、seed仕様

## HP8参照の検索結果

`rg`相当の検索により、リポジトリ内の`golem`/`ゴーレム`参照を全件確認しました。

- **変更対象**：`src/game/enemy-def.ts`のゴーレム定義（`hp: 8`）のみ。
- **変更対象外と判断したもの**：
  - `docs/history/*.md`内の過去フェーズ記録（例：`enemy-behavior-01-melee-variants.md`の「golem=8/3」等）：当時の仕様として記録されたものであり、訂正目的での書き換えは行いません。
  - `src/game/__tests__/enemy-behavior-melee-variants.test.ts`内の`createInitialEnemy('golem', ..., 8, 3, 0)`（「プレイヤー死亡後に他の敵が行動しないこと」を検証するテスト）：ゴーレムの実定義値とは無関係な、テスト内で明示的に指定したフィクスチャ値であり、HP変更に直接関係しないため変更していません。
  - `docs/rogue-of-sun-game-concept.md`：ゴーレムの名称のみの記載で、数値の記載はありません。

対象範囲は想定どおり単一ファイル・単一フィールドに限定されており、実装前に停止するような広範囲な該当はありませんでした。

## 追加・更新したテスト

`src/game/__tests__/enemy-behavior-melee-variants.test.ts` に新規describeブロック
`'golem HP boundary at real definition values (phase-07-5-golem-hp-tune)'`を追加し、以下を実測で確認しました。

- `ENEMY_DEFINITIONS.golem.hp`が実装値として`4`であること
- `ENEMY_DEFINITIONS.golem.attack`が引き続き`3`であること（HP変更の影響を受けていないこと）
- プレイヤーの通常攻撃力が`1`であること（既存実装`createInitialActor`の前提を確認）
- HP4のゴーレムがプレイヤーの通常攻撃を3回受けた時点で生存すること（HP1、`alive: true`）
- 4回目の命中で撃破され、`enemy_defeated`イベントが従来どおり発生すること

既存の`golem (slow_melee) behavior`ブロック（行動/休止周期そのものを検証するテスト）はHP定義と無関係のため変更していません。
