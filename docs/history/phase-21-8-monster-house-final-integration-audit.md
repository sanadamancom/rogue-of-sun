# Phase 21.8 モンスターハウス最終統合監査

## Phase 21.1〜21.7の実装概要

- **21.1**：候補部屋の抽出（開始/出口部屋除外）と決定的均等選定の純粋関数。production未接続。
- **21.2**：発生判定（2階・3階、独立20%ロール）、`GameMap.monsterHouse`状態型（`{roomIndex, status}`）、専用RNGストリーム、`buildFloorState`への接続。
- **21.3**：entry cellへの初回成立移動でhidden→revealed、RNG非消費、移動成立後・敵行動フェーズ前の1箇所で判定。
- **21.4**：専用敵配置。数は階層非依存で`N=clamp(ceil(sqrt(C)),4,8)`（Cは部屋サイズ由来の配置可能セル数）、`spawnSource`識別子、hidden中の行動抑止。
- **21.5**：専用報酬（固定3個、容量不足時は縮退・非throw）、既存ground item経路の完全再利用。
- **21.6**：暗所システムとの連携確認（production変更なし、既存実装が仕様を満たすことをテストのみで確認）。
- **21.7**：発覚通知「モンスターハウスだ！」を既存`GameEvent`/`formatEvents`経路で1回だけ表示。

## Phase 21で確定した最終仕様

`functional_contract`として：floor 1では発生しない／開始・出口部屋は対象外／entry cellへの成立移動で発覚／発覚は1回だけ／通知文言「モンスターハウスだ！」／専用敵・報酬はフロア生成時点で配置済み／専用報酬は通常ground item経路で取得／暗い場合も発覚し暗所状態を維持／視界外の敵・報酬を特別表示しない／同一seed・floorで決定論的に再現。

`provisional`（今回のPhase 21.8では変更せず、後続バランスPhaseへ持ち越し）：発生率（2階・3階20%）、専用敵数の算出式係数（4〜8のclamp範囲）、専用報酬数（固定3個）、敵構成（既存poolそのまま）、報酬抽選内容（既存weighted poolそのまま）、暗いモンスターハウスの実発生比率。

## 発生から再入室までのライフサイクル

1. フロア生成時（`buildFloorState`、1回のみ）：発生判定→対象部屋決定→専用敵配置→専用報酬配置。`status: 'hidden'`で開始。
2. プレイヤーがentry cellへ成立移動→`applyMonsterHouseReveal`が`status`を`'revealed'`へ変更、同ターンの敵行動フェーズ前に完了、`GameEvent`で通知1回。
3. revealed後、専用敵は通常の敵AI・戦闘経路にそのまま参加。専用報酬は既存の自動ピックアップで取得可能。
4. 退出・再入室しても`status`は`'revealed'`のまま変化せず、再通知・再生成は一切発生しない。
5. 次フロアへ遷移すると`buildFloorState`が新しい`GameMap`を`generateMap`で新規生成し、`map.monsterHouse`もその新しい`map`上でゼロから再計算される。前階の状態を参照する経路は存在しない。

## 統合監査方法

コード監査（`state.ts`の生成順序・`turn.ts`の発覚接続点を直接追跡）、4つの統合シナリオテスト（明るいMH全ライフサイクル、暗いMH全ライフサイクル、フロア遷移の状態非漏洩、決定論）、300seed×3階の統合seed監査、headlessシミュレーションによるmanual check代替。

## 明るいモンスターハウスの統合結果

300seedスイープから発見した明るいMH occurrence（floor2/3）で、hidden開始→entry cell移動で1回発覚（通知1件）→専用敵ロスターが発覚前後で不変→隣接する専用敵への攻撃が正常解決→専用報酬の自動取得成功（取得後、残り専用報酬数が正しく1減少）→退出・再入室で再通知なし→専用敵ID群が最初から最後まで安定、の全工程を1つの統合テストで確認。**PASS**。

## 暗いモンスターハウスの統合結果

既知fixture（seed3, floor2, `darkRoomIndex === monsterHouse.roomIndex`）で、hidden開始→entry cell移動で1回発覚（通知1件）→`darkRoomIndex`が発覚前後で完全不変→専用報酬の自動取得成功→退出・再入室で再通知なし、の全工程を確認。専用敵8体・専用報酬3個の生成数も既存規則どおり。**PASS**。

## floor遷移監査結果

モンスターハウス発生フロアから次フロアへ進行した際、`nextState.map`と旧`state.map`が異なるオブジェクト参照であること、次フロアの`monsterHouse`（存在する場合）が必ず新規に`status: 'hidden'`から生成されること（revealed状態が継承されないこと）、`nextState.enemies`が旧`state.enemies`と異なる配列参照であることを直接確認。モンスターハウス非発生フロアへの遷移でも専用敵・専用報酬の残存がないことを確認。**PASS**。

## ブラウザまたはheadless manual check結果

実ブラウザでの確認は本環境で実施不可のため、production関数を直接呼び出すheadlessシミュレーションで代替した。seed3/floor2（既知の暗いMH）で：生成時`status: 'hidden'`、専用敵8体・専用報酬3個確認→entry cell移動で`status: 'revealed'`、`formatEvents`出力が`['モンスターハウスだ！']`の1件のみ、`enemyActed: true`（敵フェーズ正常実行）→隣接専用敵への攻撃が正常解決→専用報酬（armor）の存在確認→退出成立→再入室時のメッセージが空配列（再通知なし）→最終`status: 'revealed'`、`darkRoomIndex`が生成時から不変（4のまま）、を全てログ出力で確認した。
